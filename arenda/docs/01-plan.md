# Заявки на аренду: план

Версия от 16.09.2026. Задача: собирать запросы «ищу жильё» из соцсетей,
передавать их арендодателям, следить, дошла ли заявка до сделки, и получать
комиссию. Главный критерий — **первые деньги как можно раньше**, остальное
докручивается по ходу.

## 1. Что приносит деньги, а что нет

Деньги приносит одна цепочка: запрос увиден быстро → арендатору ответили
первым → у арендодателя есть подходящий объект → сделка → комиссия. Софт
ускоряет первое и второе звено и не даёт потерять третье и четвёртое.
Третье звено — арендодатели и объекты — софтом не решается, это ваша
работа, и с одним арендодателем большинство запросов пройдёт мимо.

Отсюда порядок: сначала **не терять запросы и отвечать в первый час**,
потом учёт передач и комиссий, потом расширение источников и городов.

Воронка:

    источник → заявка → в работе → ответ отправлен → контакт получен
    → передана арендодателю → показ → сделка → комиссия получена

На каждом шаге — кто, когда и что дальше. Заявка, которую не взяли,
остаётся в базе с причиной.

Роли:

- **Владелец** (вы): получает заявки, отвечает арендатору, передаёт
  арендодателю, получает комиссию.
- **Арендодатель**: по-русски может не читать (во Вьетнаме — вьетнамский,
  в Ереване и Тбилиси чаще русский или английский). Получает заявку на
  своём языке, отмечает результат одним нажатием. Условия комиссии у
  каждого свои.
- **Арендатор**: системой не пользуется. С ним общаются руками там, где
  он написал, по-русски или по-английски.

## 2. География и языки

Город — самостоятельная сущность с первого дня, а не настройка «на потом»:

    Город       название, страна, часовой пояс, валюта, языки арендаторов
                (ru, en), языки арендодателей (vi / hy / ka / ru / en),
                названия города на всех языках («Нячанг», «Nha Trang»,
                «Нья Чанг») для распознавания в тексте
    Источник    привязан к городу: Telegram-чат, Facebook-группа, поиск
                Threads с набором фраз

Что из этого следует:

- **Отбор по словам — двуязычный.** Фильтр перед разбором держит наборы
  на русском («сниму», «ищу квартиру», «нужна комната», «ищем жильё») и
  английском («looking for», «apartment for rent wanted», «need a room»,
  «anyone renting»). Сами наборы лежат в настройках, не в коде.
- **Разбор — на любом языке.** Claude извлекает город, район, бюджет с
  валютой, срок, дату въезда, состав, животных, язык автора. Город берётся
  из текста, а если не назван — из источника.
- **Бюджет хранится как число + валюта** (VND, USD, AMD, GEL, RUB), без
  пересчёта. Пересчёт для сравнения с объектами — по курсу на день,
  позже.
- **Ответ арендатору** — на его языке, шаблон подставляется по языку.
- **Сообщение арендодателю** — на языке арендодателя, перевод делает
  Claude.
- **Новый город** = запись в таблице городов + список источников +
  арендодатели. Кода не требует.

Старт — Нячанг. Следующие кандидаты: Дананг (те же вьетнамские
арендодатели, те же русскоязычные чаты), Ереван, Тбилиси. Порядок — по
тому, где раньше появятся арендодатели.

## 3. Источники: API против браузера (проверено 15.09.2026)

Русскоязычный спрос в Нячанге живёт в Telegram-чатах и Facebook-группах
(«Нячанг Объявления» — больше 50 тысяч участников), реже в Threads. В
Ереване и Тбилиси — Telegram и Facebook, в Тбилиси Facebook особенно
силён. Что попадается в вашей ленте случайно — малая часть. Система
должна читать источники сама.

**API** — официальный вход: стабильно, не банят, но есть не везде.
**Браузер** — автоматизированный Chrome с залогиненным аккаунтом. Видит
всё, включая комментарии и Facebook-группы, но: правила Meta прямо
запрещают автоматический доступ, в том числе из-под залогиненного
аккаунта, и Facebook ловит его массово; вёрстка меняется и сборщик молча
слепнет; аккаунт Threads привязан к Instagram, бан уходит туда же.
Telegram, наоборот, сам выдаёт API для пользовательских клиентов (MTProto),
там браузер только хуже.

Вывод: браузер не проще, но для Facebook это единственный путь, а
Facebook — важный источник. Берём точечно, в темпе чтения человеком, с
отдельного аккаунта.

| Источник | Способ | Ограничение | Когда |
|---|---|---|---|
| **Telegram-чаты** | MTProto со второго аккаунта (gramjs) | Официально, стабильно; при первом входе с сервера нужен код из приложения | Неделя 1 |
| **Ручной вход** | Переслать в бота, «Поделиться» с телефона | Нужны ваши глаза | Неделя 1 |
| **Facebook-группы** | Playwright на сервере, профиль отдельного аккаунта, 2–3 прохода в день | Аккаунт нужно завести и прогреть 2–3 недели; группы закрытые, вступление одобряют админы | Октябрь |
| **Threads** | Сначала браузер тем же аккаунтом; после одобрения Meta — `keyword_search` (2 200 запросов/сутки) | Проверка приложения — недели | Октябрь, низкий приоритет |
| X, ВКонтакте, Instagram | — | Спроса в этих городах почти нет | Не делаем |

Claude в Chrome (расширение, работает в вашем браузере по расписанию)
годится, чтобы за вечер без кода посмотреть, сколько запросов даёт
Facebook-группа. Как постоянное решение — нет: нужен включённый
компьютер, дорого на каждый проход, и это ваш основной аккаунт.
Необязательный шаг.

## 4. Границы

- **Никаких автоматических ответов и рассылок арендаторам.** Это спам по
  правилам всех площадок и бан аккаунта. Система готовит текст, отправляете
  вы.
- **Аккаунты для чтения — отдельные.** Второй Telegram уже есть. Facebook
  (и через него Instagram → Threads) — завести и прогреть. Читающие
  сборщики ничего не лайкают, никуда не вступают, ничего не пишут.
- **Персональные данные — минимум.** Текст запроса, ссылка, ник; телефон
  только после того, как человек сам его дал. Контакт арендодателю — с
  согласия арендатора.
- **Текст постов для модели — данные, а не команды.** Разбор идёт со
  структурированным ответом по жёсткой схеме, ничего из текста не
  исполняется.
- **Сделку подтверждают двое**: арендодатель у себя, арендатор — вашим
  вопросом через неделю. Расхождение — сигнал, что комиссию обходят.

## 5. Устройство

### Данные

    Город        см. раздел 2
    Источник     город, тип (telegram / facebook / threads / manual),
                 адрес, ключевые фразы, включён ли, последний улов
    Заявка       источник, город, ссылка, автор, язык, текст, дата,
                 разбор (район, бюджет + валюта, срок, дата въезда,
                 состав, животные, уверенность), статус, причина отказа,
                 заметки
    Арендодатель имя, город, контакт (WhatsApp / Zalo / Telegram), язык,
                 условия комиссии (процент от месяца, фиксированная сумма
                 или доля первого платежа), объекты
    Объект       город, район, тип, цена + валюта, срок, свободен с,
                 описание
    Передача     заявка → арендодатель, когда, чем ответил, статус
                 (показ / сделка / отказ / молчит)
    Сделка       передача, дата, сумма аренды, комиссия, ожидается до,
                 получена когда
    Событие      журнал всех переходов

У каждой записи `id` (UUIDv7), `createdAt`, `updatedAt`; удаление —
пометка, не удаление строки.

### Части

1. **Сборщики** пишут сырые сообщения в `inbox`:
   - `telegram-collector`: gramjs, список чатов из таблицы источников,
     двуязычный фильтр по словам.
   - `inbox-bot`: Telegram-бот, принимает пересланное сообщение или ссылку.
   - `browser-collector` (октябрь): Chrome с профилем отдельного аккаунта,
     Facebook-группы и поиск Threads.
2. **Разбор**: дедупликация (та же ссылка или тот же автор с тем же
   текстом за сутки), классификация и извлечение через Claude API
   (`claude-opus-5`, структурированный ответ), оценка совпадения с
   объектами города.
3. **Бот владельца** — в первую неделю это и есть весь интерфейс:
   - Заявка приходит сообщением: разбор, ссылка на пост, готовый ответ
     на языке автора, кнопки «в работу / мимо / передать → список
     арендодателей».
   - «Передать» готовит сообщение на языке арендодателя со ссылкой на
     страницу заявки и кнопку «Отправить в WhatsApp» (`wa.me/<номер>?text=`),
     чат открывается с готовым текстом.
   - Команды: `/today` — что в работе, `/deals` — что ожидается по
     комиссиям.
4. **Страница для арендодателя** — по токену, без логина, на его языке:
   заявка и кнопки «показ / сделка / отказ». Работает в любом мессенджере.
   Ни у WhatsApp, ни у Zalo нет API для личных сообщений: Cloud API и
   официальные аккаунты требуют верификации бизнеса и платы за диалог.
5. **Кабинет** (недели 2–3): лента с фильтром по городу, карточки,
   арендодатели и объекты, сделки и комиссии с просрочками, настройки
   городов, источников и фраз. Бот остаётся для уведомлений.

### Стек

- TypeScript везде. Сервер — Node + Hono, база — SQLite (`better-sqlite3`),
  резервная копия — файл в Hetzner Storage Box или просто копия по cron.
- Бот — grammY. Чтение Telegram — gramjs (MTProto).
- Кабинет — Preact + Vite.
- LLM — `@anthropic-ai/sdk`.
- Размещение — Hetzner, самый маленький тариф (около 4–5 € в месяц),
  Docker Compose. Страницам для арендодателей нужен адрес: до покупки
  домена — бесплатное имя вида `<ip>.sslip.io` с сертификатом от Caddy.
- Публикация через GitHub Actions по правилу: «готово» только после
  успешного `deploy`. Настройки показывают дату сборки и коммит.
- Проверки: vitest на разбор, правила статусов и фильтры; Playwright-прогон
  кабинета со скриншотами.

## 7. Что мерить

- Заявок в день по источникам и городам; доля взятых в работу.
- Время от заявки до вашего ответа. Это главная метрика первой недели.
- Доля ответивших, доля давших контакт.
- Переданных, показов, сделок.
- Комиссий: ожидается, просрочено, получено.

## 8. Решения

- Рынок на старте — Нячанг; арендаторы по-русски и по-английски.
- Арендодатель пока один, в WhatsApp. Условия у каждого свои.
- Пассивный поток «что попалось в ленте» не считаем.
- Сервер — Hetzner.
- Второй Telegram есть, им читаем. Facebook-аккаунт заводится сейчас, с
  настоящего номера и с телефона, прогрев 2–3 недели.
- Заявка на Threads API — с основного аккаунта: официальный API не
  нарушает правил, а свежие аккаунты на проверке отклоняют. Токен — со
  второго аккаунта как тестового пользователя приложения.
- Репозиторий — `belinsky2/arenda-project`.
