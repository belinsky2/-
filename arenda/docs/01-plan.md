# Заявки на аренду: план

Задача: собирать запросы «ищу жильё» из соцсетей, передавать их арендодателям,
следить, дошла ли заявка до сделки, и получать комиссию.

Это отдельный проект. С «Панчлайном» у него общая только папка репозитория,
поэтому всё лежит в `arenda/`, а правила из корневого `CLAUDE.md` (тексты
Картер, `labels.ts`, эталон на Kotlin) к нему не относятся. Когда проект
оживёт, его стоит вынести в отдельный репозиторий: перенос папки — одна команда.

## 1. Что должно получиться

Воронка, которую видит владелец:

    источник → заявка → отобрана → ответ отправлен → контакт получен
    → передана арендодателю → показ → сделка → комиссия получена

На каждом шаге — кто, когда и что дальше. Ничего не теряется: заявка,
которую не взяли в работу, остаётся в базе с причиной.

Три роли:

- **Владелец** (вы): видит ленту заявок, отбирает, отвечает, передаёт,
  получает комиссию.
- **Арендодатель**: получает переданную заявку, отмечает результат
  (показ, сделка, отказ), видит, что должен.
- **Арендатор**: не пользуется системой. С ним общаются руками в той сети,
  где он написал.

## 2. Источники: что реально доступно (проверено 15.09.2026)

| Источник | Как читать | Комментарии к постам | Ограничения | Приоритет |
|---|---|---|---|---|
| **Threads** | Официальный API, `keyword_search` | Ответы к чужим постам: только топ 20–30 через API | 2 200 запросов/сутки на пользователя, нужна проверка приложения Meta (`threads_keyword_search`) | 1 |
| **Telegram-группы** | MTProto от имени вашего аккаунта (gramjs), читает всё как обычный клиент | Обсуждения = те же сообщения | Бот (Bot API) видит сообщения только если добавлен в группу и у него выключен privacy mode, поэтому нужен именно пользовательский аккаунт | 1 |
| **Ручной вход** | Переслать сообщение в бота или поделиться ссылкой из любого приложения | Любой комментарий копируется руками | Нет ограничений, но нужны ваши глаза | 1 (стартовый) |
| **X** | API v2, поиск свежих постов | Ответы доступны | Только оплата за запрос: 0,005 $ за прочитанный пост; тариф Basic за 200 $/мес закрыт для новых с февраля 2026 | 3, после замера объёма |
| **Facebook-группы** | API нет: Groups API убран в апреле 2024 | — | Только ручной вход или расширение в браузере | ручной |
| **ВКонтакте** | `newsfeed.search` с пользовательским токеном | Комментарии отдельным методом | Нестабильно отдаёт пустые ответы; актуально только для русскоязычного рынка в РФ | 3 |
| **Instagram** | Поиска по тексту постов нет | — | Только ручной вход | ручной |

Выводы для архитектуры:

1. **Ручной вход обязателен и должен быть первым.** Он покрывает все сети
   разом, включая комментарии, которые API не отдаёт. Threads и Telegram
   потом просто наполняют ту же ленту сами.
2. **Комментарии под чужими постами — слабое место любого API.** Threads
   отдаёт только популярные ответы. Поэтому в ручном входе должна быть
   одна кнопка «переслать» без заполнения форм: увидели комментарий,
   поделились, разбор сделает система.
3. **Threads API требует заявки в Meta.** Это недели, не дни. Подать заявку
   стоит в первую неделю, параллельно с MVP.

## 3. Границы, которые лучше не нарушать

- **Никаких автоматических ответов и рассылок арендаторам.** Это спам по
  правилам всех площадок и быстрый бан аккаунта, через который читаются
  группы. Система готовит текст ответа, отправляете вы.
- **Персональные данные.** Храним минимум: текст запроса, ссылку на пост,
  ник, а телефон только после того, как человек сам его дал. Передача
  контакта арендодателю — после согласия арендатора («могу передать ваш
  номер хозяину квартиры?»). Это и юридически чище, и конверсию не портит.
- **Аккаунт для чтения Telegram — отдельный**, не ваш основной. При
  блокировке теряется он, а не переписка с клиентами.
- **Сделку подтверждают двое.** Арендодатель отмечает у себя, а арендатору
  вы через неделю пишете «как заехали?». Расхождение — сигнал, что
  комиссию пытаются обойти.

## 4. Устройство

### Данные

    Заявка      источник, ссылка, автор, текст, дата, разбор (город, район,
                бюджет, срок, дата въезда, состав, особенности), статус,
                причина отказа, заметки
    Арендодатель имя, контакт (Telegram), условия комиссии (процент или
                фиксированная сумма), объекты
    Объект      адрес/район, тип, цена, срок, свободен с, описание
    Передача    заявка → арендодатель, когда, чем ответил, статус
                (показ / сделка / отказ / молчит)
    Сделка      передача, дата, сумма аренды, комиссия, ожидается до,
                получена когда, чем
    Событие     журнал всех переходов: кто, что, когда

У каждой записи `id` (UUIDv7), `createdAt`, `updatedAt`, удаление —
пометка, не удаление строки. То же правило, что в «Панчлайне»: материал
не теряется.

### Части

1. **Сборщики** — отдельные процессы, каждый пишет сырые сообщения в
   таблицу `inbox`:
   - `inbox-bot`: Telegram-бот, куда вы пересылаете сообщения и ссылки.
     Заодно принимает ссылку из «Поделиться» на телефоне.
   - `threads-collector`: опрос `keyword_search` по списку ключевых фраз
     («ищу квартиру», «сниму», «нужна комната», по городам).
   - `telegram-collector`: gramjs-клиент, подписан на список групп,
     фильтр по ключевым словам до отправки в разбор.
2. **Разбор** — одна функция над каждым сообщением из `inbox`:
   - Дедупликация: та же ссылка, тот же автор с тем же текстом за сутки.
   - Классификация и извлечение через Claude API, модель `claude-opus-5`,
     структурированный ответ (`output_config.format`): является ли это
     запросом арендатора (а не предложением, не спамом, не риелтором),
     город, район, бюджет, срок, дата, состав, животные, уверенность.
     Стоимость при 300 сообщениях в день незначительна; если объём
     вырастет на порядок, замерить качество на `claude-haiku-4-5`.
   - Оценка: совпадение с объектами арендодателей (город, бюджет, срок).
3. **Кабинет** — веб-приложение для вас:
   - Лента новых заявок с разбором и оценкой, кнопки «в работу» / «мимо»
     с причиной.
   - Карточка заявки: шаблон ответа, статус, история, передача
     арендодателю в один клик (список подходящих объектов сверху).
   - Арендодатели и объекты.
   - Сделки и комиссии: что ожидается, что просрочено, что получено.
   - Настройки: ключевые слова, группы, города.
4. **Уведомления** — тот же Telegram-бот:
   - Вам: новая заявка с высокой оценкой, напоминание «арендодатель не
     ответил три дня», «комиссия просрочена».
   - Арендодателю: переданная заявка с кнопками «показ», «сделка»,
     «отказ». Ему не нужен кабинет, достаточно бота.

### Стек

- **TypeScript везде**, как в `web/`: один язык, одни инструменты.
- Сервер: Node, Hono, SQLite через `better-sqlite3` на старте (одна
  машина, один пользователь, резервная копия — файл). Переход на Postgres
  при появлении второго оператора.
- Бот: grammY. Чтение Telegram: gramjs (MTProto).
- Кабинет: Preact + Vite, как в `web/`, но это отдельный пакет.
- LLM: `@anthropic-ai/sdk`.
- Размещение: один VPS, `systemd` или Docker Compose. Публикация через
  GitHub Actions по тому же правилу, что в корневом `CLAUDE.md`: «готово»
  только после успешного `deploy`.
- Проверки: vitest на разбор и правила статусов, Playwright-прогон
  кабинета со скриншотами.

## 5. Этапы

### Этап 0. Уточнения (нужны ваши ответы, см. раздел 7)

Город и язык рынка, число арендодателей и объектов, объём запросов,
условия комиссии. От этого зависят ключевые слова и структура разбора.

### Этап 1. MVP на ручном входе (одна-две недели)

Уже приносит деньги: заменяет заметки и переписку, которые сейчас
живут в голове.

- Бот принимает пересланное сообщение или ссылку → заявка в базе.
- Разбор через Claude, дедупликация.
- Кабинет: лента, карточка, статусы, арендодатели, объекты, передача.
- Бот арендодателю: заявка с кнопками результата.
- Сделки и комиссии, напоминания.
- Параллельно: заявка в Meta на доступ к Threads API.

### Этап 2. Автосбор

- Threads: `keyword_search` по фразам и городам, каждые 15 минут.
- Telegram: gramjs-клиент по списку групп.
- Настройки ключевых слов и групп в кабинете.
- Оценка совпадения заявка ↔ объект и сортировка ленты по ней.

### Этап 3. Контроль и отчёты

- Двойное подтверждение сделки (арендодатель + вопрос арендатору).
- Отчёт по месяцу: заявок, передано, сделок, комиссий получено и
  просрочено, по арендодателям и по источникам.
- Шаблоны ответов с подстановкой разбора.

### Этап 4. Другие сети по замеру

- X: две недели считать по ручному входу, сколько заявок приходит оттуда;
  при цене 0,005 $ за прочитанный пост оценить бюджет.
- ВКонтакте: только если рынок в РФ.
- Facebook и Instagram остаются на ручном входе.

## 6. Что мерить

- Заявок в день по источникам; доля, отобранная в работу.
- Доля ответивших, доля давших контакт.
- Переданных, показов, сделок.
- Комиссий: ожидается, просрочено, получено.
- Время от заявки до передачи. Заявки стареют быстро: человек, ищущий
  квартиру, находит её за дни.

## 7. Вопросы, без которых не начать

1. Какой город или города и на каком языке пишут арендаторы?
2. Сколько сейчас арендодателей и объектов? Условия комиссии одинаковые
   у всех или у каждого свои?
3. Сколько запросов в день вы видите руками сейчас? Это определяет,
   нужен ли автосбор в первую очередь или достаточно ручного входа.
4. Какие Telegram-группы читать? Есть ли отдельный аккаунт для этого?
5. Есть ли аккаунт разработчика Meta, чтобы подать заявку на Threads API?
6. Где размещать: есть VPS, или подобрать?
7. Оставить проект в этом репозитории в `arenda/` или сразу завести
   отдельный?
