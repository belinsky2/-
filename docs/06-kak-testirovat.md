# Как протестировать

## Честное состояние

Код собирается, 56 тестов логики зелёные. **Но приложение ни разу не запускалось** —
ни на телефоне, ни в эмуляторе. В среде разработки нет Android SDK, а в CI нет
устройства. Всё, что проверено, — что оно компилируется и что доменные правила
считают правильно.

Практически это значит: **вероятность падения на первом запуске высокая.**
Это нормально для кода, который никто не запускал; ненормально было бы
называть его готовым.

## Что ставить

В артефактах сборки два APK:

| Артефакт | Что это |
|---|---|
| `punchline-debug-apk` | **Ставь этот.** Подписан ключом, который генерирует сам Android-плагин, — работает без секретов. Отдельное приложение (суффикс `.debug`) |
| `punchline-release-apk` | Появится, когда добавишь четыре секрета. Пока называется `punchline-UNSIGNED-do-not-install` и не установится |

Данные из debug-версии **не перенесутся** в релизную: для Android это два разных
приложения. Поэтому пока это проверка, а не начало работы — не вноси туда
материал, который жалко потерять.

## Куда нажимать

1. **Actions** → последний прогон `android` → внизу **Artifacts** → `punchline-debug-apk`.
2. Скачается ZIP, внутри `app-debug.apk`. Перекинь на телефон.
3. Открой файловым менеджером. Android спросит разрешение на установку из этого
   источника: Настройки → Приложения → Особый доступ → Установка неизвестных приложений.
4. Play Защита покажет «Приложение заблокировано для защиты устройства».
   **Нажимать надо неприметную строку «Все равно установить», а не синюю «ОК».**
   Синяя кнопка — это отказ; после неё приходит «Приложение не установлено»,
   и выглядит это так, будто сломался APK. Google намеренно сделал согласие
   невзрачным текстом, а отказ — крупной яркой кнопкой.

   Если строка не нажимается: Google Play → аватарка → Play Защита →
   шестерёнка → выключить «Проверять приложения на угрозы безопасности».

   Предупреждение «Play Защита никогда не проверяла приложение этого
   разработчика» — норма для любой самостоятельно собранной сборки,
   а не признак проблемы с приложением.

## Порядок проверки

Идти по цепочке методики, а не по экранам: так сломается то, что важно.

| # | Что сделать | Что должно произойти |
|---|---|---|
| 1 | Открыть приложение | Экран «Сегодня»: цепочка 0 дней, 0 из 5 минут. **Не должно упасть** |
| 2 | Вкладка «Практика» | Список из 48 упражнений по частям книги. У семи вместо названия — «Упражнение N» |
| 3 | Открыть упражнение 20, вписать название | После сохранения название остаётся |
| 4 | Вкладка «Темы» → добавить тему | Появляется карточка со слайдером |
| 5 | Подвигать слайдер, нажать «Главная» | Оценка сохраняется; на четвёртой главной теме — предупреждение |
| 6 | «Ассоциации» → добавить узел → «Ветвить» → добавить ещё | Второй узел с отступом под первым |
| 7 | На узле «В шутку» | Узел помечается «Уже в работе» |
| 8 | «Рант» → «Начать рант» | Запрос доступа к микрофону, таймер идёт |
| 9 | «Стоп» | «Записано, N сек» |
| 10 | Вкладка «Материал» → открыть шутку | Визард на шаге «Отношение» |
| 11 | Пройти шаги: отношение → премиса → панч | На доске статус меняется на «Черновик» |
| 12 | Вкладка «Сеты» → создать сет на 5 минут | Появляется в списке |
| 13 | «Собрать» → нажать на кандидата | Шутка встаёт в сет, снизу список кандидатов |
| 14 | «На сцену» → «Это репетиция» | Чёрный экран, крупные слова, таймер идёт, экран не гаснет |
| 15 | Тап по экрану | Переход к следующему номеру |
| 16 | «Закончил» | Экран разбора со списком шуток из сета |
| 17 | Отметить реакции, «Пересобрать акт» | Список изменений («шутка → Обкатана») |
| 18 | Вкладка «Дневник» → написать текст → сохранить | Цепочка становится 1 день |
| 19 | «Сегодня» → «Перенос данных» → «Выгрузить всё в файл» | Файл сохраняется |
| 20 | Там же «Выгрузить текст в Markdown» | Открой файл — структура «Мой акт / В работе / Архив» |

## Что сообщить мне

Для падения нужен не «упало», а место и текст. Проще всего:

- **на каком шаге** из таблицы выше;
- **что было на экране** (скриншот);
- если приложение закрылось — лог. На S24 Ultra без компьютера его снять сложно,
  поэтому достаточно номера шага: по нему я почти всегда пойму, где искать.

Если есть компьютер с Android-платформой:
```bash
adb logcat --pid=$(adb shell pidof -s ru.punchline.workbook.debug)
```

## Чего в приложении осознанно нет

- Транскрипта рантов — пишется только аудио.
- Напоминания об утренних страницах.
- Прослушивания записей: аудио сохраняется и попадает в бэкап, но экрана плеера нет.
- Экрана настроек: цель по времени зашита на 5 минут.
