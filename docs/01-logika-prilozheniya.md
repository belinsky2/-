# Comedy Workbook App — логика работы

Мобильное приложение, переносящее методику Джуди Картер
(*The NEW Comedy Bible*, 2020 + *The Comedy Bible Workbook*) в цифровую рабочую тетрадь.

Документ описывает **что приложение делает и по каким правилам**. План разработки — отдельно.

---

## 0. Источник: что именно мы переносим

### 0.1. Структура рабочей тетради (5 секций)

| # | Секция тетради | Назначение |
|---|---|---|
| 1 | **48 Exercises to Turn Problems into Punchlines** | Пронумерованные упражнения из книги, каждое со своим полем для ответа |
| 2 | **Jokes in Progress by Topic** | Сырьё: черновики шуток, сгруппированные по темам |
| 3 | **My Act: Polished Jokes by Topic** | Отобранный, обкатанный материал |
| 4 | **Set Lists** | Порядок номеров под конкретный хронометраж и тему |
| 5 | **Morning Writings** | 30 писчих промптов, ежедневная практика |

Эти пять секций — **каркас навигации приложения**. Пять разделов = пять вкладок.

### 0.2. Структура книги (сквозная линия обучения)

- **Пролог + Введение**: Ten Commandments of Comedy; Ex. 1 «Where are you on the Funny Scale?», Ex. 2 «Commit to Your Comedy Vision».
- **Part One — Warm-Up: Overcoming Creative Anxiety**: стратегия Сайнфелда (не рвать цепочку), настройка тетради, утренние страницы, поиск площадки для открытого микрофона, борьба со страхом сцены, поиск Comedy Buddy.
- **Part Two — Stand-up Comedy Workshop: 13 упражнений на письмо**: поиск аутентичных тем → выбор 3 лучших → mind-map → rant & rave → act-outs → организация «jokes in progress» → space work → payoffs (turn, list of three).
- **Part Three — Выступление**: комедийная персона, страх сцены через сет-лист, работа с хеклерами, провал и восстановление, редактура и порядок номеров.
- **Part Four — 8 дополнительных промптов**, чтобы добрать до часа материала (напр. Ex. 38 «Self-Mocking Opening»).

### 0.3. Анатомия шутки по Картер (ядро доменной модели)

```
ТЕМА (topic)
  └─ ОТНОШЕНИЕ (attitude): hard / weird / scary / stupid
       └─ ПРЕМИСА (premise): «Самое [attitude] в [topic] — это ...»
            └─ ПАНЧ (payoff): mix / turn / list of three
                 └─ ACT-OUT: показать, а не описать
                      └─ SPACE WORK: работа с воображаемым пространством
                           └─ TAG / CALLBACK
```

**Правило-инвариант приложения:** шутка не может быть помечена «готовой», если у неё нет
темы, отношения, премисы и панча. Act-out — сильная рекомендация, отслеживается метрикой.

### ⚠️ Про копирайт

Приложение **не содержит текст книги**: ни формулировок упражнений целиком, ни примеров шуток
Картер. Хранятся только: номер упражнения, короткий рабочий заголовок, тип поля ввода
и ссылка «см. стр. N книги». Весь контент — пользовательский. Это и юридически чисто,
и честно по отношению к автору (Заповедь №1: Thou Shall Not Steal).

## 1. Продуктовые принципы

1. **Тетрадь, а не соцсеть.** Одиночная работа + опционально один Comedy Buddy. Никаких лент и лайков.
2. **Голос — первичный ввод.** Стендап пишется вслух. Диктофон доступен в один тап с любого экрана; текст — производная от аудио.
3. **Offline-first.** Идеи приходят в метро и на кухне. Всё пишется локально, синк — фоном.
4. **Одна цепочка в день.** Метрика №1 — не количество шуток, а непрерывность (Seinfeld Strategy).
5. **Материал живёт, а не хранится.** У каждой шутки есть состояние и история прогонов; «архив» — это тоже состояние, а не помойка.
6. **Меньше полей.** На экране быстрой записи — одно поле и кнопка записи. Разметка на элементы — потом, в режиме воркшопа.

## 2. Доменная модель

### 2.1. Основные сущности

**Profile** — хранится в Room, как и всё пользовательское (переживает смену телефона; 05 §1.2)
`id, name, comedyVision (Ex.2), funnyScaleHistory[{date, score 1–10}] (Ex.1), goalMinutes (напр. 5/15/30/60), buddyId?, timezone, morningWritingTime`

**Topic** — тема
`id, title, source (brainstorm | rant | morning | gig), attitudes[], passionScore 0–10, isCore (одна из 3 главных), status (candidate | core | parked), mindMapId?, createdAt`
- Из упражнения «30 тем → выбери 3»: `passionScore` — «сколько во мне злости/страсти по этому поводу».
- `isCore = true` максимум у 3 тем одновременно (мягкое ограничение с предупреждением).

**MindMap**
`id, topicId, nodes[{id, parentId?, text, order, kind: branch|premise-candidate}]`
- Представление в v1 — дерево-аутлайн (вложенный список), не свободный холст:
  методике важно ветвление ассоциаций, а не координаты (см. аудит, 05 §2.1).
- Любой узел одним действием превращается в `Bit` со статусом `seed`.

**Bit** (единица материала: шутка / кусок)
`id, topicId, title, status, attitude, elements{}, tags[], durationSec (замер), createdAt, updatedAt, originExerciseId?, originRantId?`

**BitElements** (структурированное тело шутки)
```
premise: text
setup: text
punch: { text, technique: mix | turn | list-of-three | self-mocking | other }
actOut: { text, hasSpaceWork: bool, audioId? }
tags: [text]        // добивки
callbackToBitId?: id
```

**BitVersion** — снапшот на каждое существенное изменение
`id, bitId, elementsSnapshot, note, createdAt` — чтобы вернуться к «той версии, что зашла в среду».

**Rant** — упражнение «rant & rave»
`id, topicId?, audioId, transcript?, durationSec, extractedBitIds[], createdAt`

**Exercise** — справочник, 48 позиций
`id (1–48), part (intro|1|2|3|4), order, shortTitle, bookPage, inputSchema, producesEntity (topic|bit|setlist|note|none), prerequisiteIds[]`
- `inputSchema` — декларативное описание формы: список полей (`text`, `longtext`, `list`, `scale`, `audio`, `topic-picker`, `bit-picker`).

**ExerciseEntry** — ответ пользователя
`id, exerciseId, answers{}, status (not-started | in-progress | done), completedAt, generatedEntityIds[]`

**MorningWritingPrompt** — справочник, 30 позиций
`id (1–30), shortTitle`

**MorningWritingEntry**
`id, promptId?, date, text, audioId?, wordCount, harvestedBitIds[]`
- «Harvest»: выделил кусок текста → создал `Bit` со статусом `seed`, ссылка сохраняется в обе стороны.

**SetList**
`id, title, targetDurationSec, theme?, items[], venueTypeHint?, createdAt`

**SetListItem**
`id, bitId, order, plannedDurationSec, role (opener | body | closer | callback | filler), notes`

**Gig** — выступление или прогон
`id, setListId?, type (open-mic | showcase | paid | rehearsal), venue, date, plannedDurationSec, actualDurationSec, audioId?, audienceSize?, selfRating 1–5, notes`

**BitPerformance** — как конкретная шутка отработала на конкретном выступлении
`id, gigId, bitId, laughResult (silence | chuckle | laugh | big-laugh | applause-break), keptOrCut, note`
- Это главный источник данных для «повышения» шутки в `polished` и для отсева.

**Streak** — цепочка Сайнфелда
`date, didWrite (bool), didPerform (bool), minutesWritten`

**Buddy / ShareLink**
`buddyId, sharedBitIds[], permission (view | comment)` — обмен материалом с напарником, комментарии по шутке.

### 2.2. Связи

```
Profile ─< Topic ─< Bit ─< BitVersion
                     │
                     ├─< BitPerformance >─ Gig >─ SetList >─< SetListItem
                     │
Exercise ─< ExerciseEntry ──generates──> Topic | Bit | SetList
MorningWritingEntry ──harvest──> Bit
Rant ──extract──> Bit
MindMap.node ──promote──> Bit
```

## 3. Жизненный цикл шутки (state machine)

Это сердце приложения — цифровой эквивалент перекладывания листка из секции 2 в секцию 3 тетради.

```
  seed ──> premise ──> draft ──> tested ──> polished
    │         │          │         │           │
    └─────────┴──────────┴─────────┴──────> parked / retired
```

Состояние «в сет-листе, ждёт прогона» **не хранится** — оно вычисляется из связи
`SetListItem → Bit` и показывается бейджем (05 §2.3): хранимый статус, дублирующий связь,
неизбежно рассинхронизируется.

| Статус | Что это | Где виден | Условие перехода дальше |
|---|---|---|---|
| `seed` | Голая идея, фраза, узел mind-map, кусок утренних страниц | Inbox | Сформулирована премиса + выбрано attitude |
| `premise` | Есть тема + отношение + премиса, панча нет | Jokes in Progress | Добавлен `punch.text` |
| `draft` | Полная шутка на бумаге, не проверена залом | Jokes in Progress (бейдж «в сете», если стоит в сет-листе) | Есть ≥1 `BitPerformance` |
| `tested` | Обкатана ≥1 раз | Jokes in Progress (с бейджем результата) | ≥2 выступления с результатом ≥ `laugh` |
| `polished` | Рабочий материал акта | **My Act** | — |
| `parked` | Отложена, но не выброшена | Архив (фильтр) | Можно вернуть в любой статус |
| `retired` | Не работает / отыграна | Архив | — |

**Автоматические подсказки движка:**
- 3 подряд `silence` → предложить `parked` с вопросом «переписать премису или отношение?».
- `draft` без изменений 30 дней → в еженедельный дайджест «застряло».
- `polished` без выступлений 90 дней → «пора вернуть в сет».
- Шутка без `actOut` в статусе `tested` → подсказка «Ex. 12: добавь act-out».

## 4. Ключевые сценарии (флоу)

### 4.1. Онбординг (1 раз, ~10 минут)
1. Ex. 1 — шкала смешного: слайдер 1–10 + «почему». Сохраняется как первая точка графика.
2. Ex. 2 — Comedy Vision: одно предложение «Через год я...». Закрепляется на главном экране.
3. Цель по времени акта: 5 / 15 / 30 / 60 минут → определяет прогресс-бар «My Act».
4. Время утренних страниц → локальное напоминание.
5. Ten Commandments — экран-чеклист, принимается один раз (свои формулировки-пересказы, не цитаты).

### 4.2. Ежедневный цикл
```
Утро:  напоминание → Morning Writings (таймер, свободный текст/голос)
        └─ по окончании: «Выдели то, что зацепило» → Bits со статусом seed
День:  Quick Capture (виджет / шорткат) → seed в Inbox
Вечер: Workshop — разбор Inbox: seed → premise → draft
        └─ закрыть день: отметить цепочку Сайнфелда
```

### 4.3. Воркшоп темы (Part Two, ядро)
```
1. Brainstorm тем        (список, быстрый ввод, до 30 шт.)
2. Оценка страсти        (свайп/слайдер по каждой теме)
3. Выбор 3 главных       (isCore)
4. Mind-map по каждой    (холст, узлы, promote → seed)
5. Rant & Rave           (диктофон, 2–3 мин на тему, без остановки)
6. Разбор рантa          (транскрипт → выделение → premise)
7. Attitude              (hard / weird / scary / stupid — обязательный выбор)
8. Premise               (шаблон-подсказка «Самое ___ в ___ — это ...»)
9. Payoff                (выбор техники: mix / turn / list of three)
10. Act-out              (запись голосом + пометка «space work есть/нет»)
11. Tags                 (добивки списком)
→ статус draft
```
Экран воркшопа — **пошаговый визард с возможностью выйти на любом шаге**; прогресс шага
сохраняется, шутка живёт в промежуточном статусе.

### 4.4. Сборка сет-листа
1. Указать хронометраж (5 / 7 / 10 / 15 / 30 / 60) и тему/площадку.
2. Кандидаты: `polished` + `tested` по выбранным темам, отсортированные по среднему `laughResult`.
3. Drag & drop в порядок; для каждой позиции — роль (opener / body / closer / callback).
4. Живая сумма хронометража vs цель; предупреждение при перерасходе.
5. Проверки движка:
   - `callback` не может стоять раньше шутки, на которую ссылается;
   - две подряд шутки на одну тему → подсказка «разбавь»;
   - closer должен иметь лучший средний результат в сете.
6. **Режим сцены**: крупные cue-слова (не полный текст), таймер обратного отсчёта, вибро на «свет», автозапись аудио.

### 4.5. После выступления (замыкание петли)
1. Открыть гиг → пройти по списку шуток → отметить результат каждой одним тапом.
2. Общая заметка + самооценка 1–5.
3. Аудио выступления автоматически привязывается к гигу; можно ставить метки прямо во время прослушивания.
4. Движок пересчитывает статистику шуток и предлагает переходы статусов.
5. Новые идеи, родившиеся на сцене («это надо запомнить») → `seed` в Inbox.

### 4.6. Comedy Buddy
- Расшарить конкретную шутку или сет-лист по ссылке.
- Напарник видит текст и слышит act-out; оставляет комментарий с меткой «работает / не понял / переписать».
- Комментарии не редактируют шутку — только висят сбоку.

## 5. Навигация (5 вкладок = 5 секций тетради)

```
┌──────────┬───────────┬─────────┬──────────┬─────────┐
│ Практика │  Материал │  Мой акт│ Сет-листы│ Дневник │
└──────────┴───────────┴─────────┴──────────┴─────────┘
```

1. **Практика** — 48 упражнений, сгруппированные по частям книги; прогресс-кольца; следующее рекомендованное упражнение сверху.
2. **Материал** (*Jokes in Progress*) — доска шуток, сгруппированных по темам; фильтры по статусу/отношению/технике панча; Inbox сверху.
3. **Мой акт** (*My Act*) — только `polished`, сгруппированы по темам, суммарный хронометраж и прогресс к цели (например, 23 из 60 минут).
4. **Сет-листы** — список сетов + гиги + история выступлений и статистика.
5. **Дневник** (*Morning Writings*) — календарь-цепочка, сегодняшний промпт, архив записей.

**Сквозные элементы:** FAB «Записать» (текст/голос) на всех вкладках; глобальный поиск по всему тексту и транскриптам.

## 6. Метрики и прогресс

**Главные (на домашнем экране):**
- 🔥 Цепочка: N дней подряд (Seinfeld Strategy).
- ⏱ Готового материала: X мин из цели Y.
- 🎤 Выступлений за 30 дней.

**Вторичные (в разделе статистики):**
- Конверсия воронки: `seed → premise → draft → tested → polished` (проценты и «где затык»).
- LPM (laughs per minute) по последним гигам.
- Топ-5 и худшие-5 шуток по среднему результату.
- Распределение по attitude — показывает перекос («у тебя 80% hard, попробуй weird»).
- Доля шуток с act-out (Картер настаивает: играть, а не рассказывать).
- Средний возраст материала в `draft` — индикатор «пишу, но не выношу на сцену».

## 7. Технические решения, вытекающие из логики

| Требование | Решение |
|---|---|
| Ввод голосом первичен | Встроенный рекордер + локальная транскрипция (on-device speech-to-text), аудио хранится всегда, транскрипт — вспомогательный |
| Offline-first | Локальная БД как источник истины; конфликты при будущем слиянии — last-write-wins **на уровне записи**, проигравшая версия сохраняется в `BitVersion` (04 §3.3, 05 §1.3) |
| История версий шутки | Снапшот при каждом изменении структурных полей, но не чаще 1 раза в 5 минут |
| 48 упражнений без хардкода экранов | Декларативный `inputSchema` → рендерер форм. Новое упражнение = запись в справочнике, не релиз |
| Приватность | Материал — интеллектуальная собственность. Модель защиты: системное шифрование Android (FBE) + приложение без доступа в сеть + никакой аналитики. Отдельное шифрование БД не вводится — оно не защитило бы экспорт и синк-папку (05 §1.1) |
| Экспорт | Markdown / PDF по секциям тетради + отдельный экспорт сет-листа «в карман» (одна страница cue-слов) |
| Режим сцены | Экран не гаснет, тёмная тема, крупный шрифт, работа без сети, только жесты (тап — следующая шутка) |

## 8. Роль ИИ (опционально, строго вторично)

ИИ **не пишет шутки** — это нарушает и методику (аутентичность), и Заповеди.
Допустимые роли:
- Транскрипция и разметка рантов на смысловые блоки.
- «Найди в моих утренних страницах повторяющиеся темы» — кластеризация по темам.
- Спарринг-вопросы по методике: «А что тут самое hard? А ты это показал или рассказал?»
- Проверка структуры: «в этой шутке нет панча / act-out описан, а не сыгран».

Всё — как опция с явным переключателем, работающая на серверной модели, с предупреждением
о том, что текст покидает устройство.

## 9. Принятые решения

Ответы получены, зафиксированы в `03-plan-razrabotki.md`:

- Платформа — только Android (Samsung Galaxy S24 Ultra), нативный Kotlin.
- Только для личного использования — без публикации в Google Play.
- Язык интерфейса и материала — русский.
- Синхронизация не нужна: всё локально, приложению не требуется даже разрешение `INTERNET`.
- Comedy Buddy (раздел 4.6) переносится в v2; в v1 упражнение 7 — заглушка.
- Тетради на руках нет: состав упражнений восстановлен по открытым источникам,
  см. `02-katalog-uprazhneniy.md`. Семь названий и 30 промптов утренних страниц
  вносятся в приложении вручную, без пересборки.
