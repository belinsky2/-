# План разработки

> **Обновлено после архитектурного разбора.** Требование «синхронизация с Mac в будущем +
> смена телефона без потери данных» изменило слой данных и порядок этапов.
> Обоснование каждого изменения — в `04-arhitekturnyy-razbor.md`.

## 1. Зафиксированные решения

| Вопрос | Решение | Следствие |
|---|---|---|
| Платформа | **Только Android**, целевое устройство Samsung Galaxy S24 Ultra | Нативный Kotlin, никаких кросс-платформенных прослоек |
| Аудитория | **Только для себя** | Не нужен Google Play, аккаунт разработчика, политика конфиденциальности, локализация |
| Язык | **Русский** | Единственная локаль; распознавание речи — ru-RU |
| Синхронизация | **Не в v1, но обязательна в v2** (Mac) | Слой данных проектируется под слияние с первого дня: UUIDv7, tombstones, `updatedAt`, аудио по хешу |
| Смена телефона | **Требование v1** | Экспорт/импорт хранилища — этап M1.5, а не в конце |
| Comedy Buddy | **v2** | Упражнение 7 в v1 — заглушка-чеклист |
| Раздача другим людям | Возможна с самого начала | Release-keystore и финальное имя пакета фиксируются на M0 |

**Приложению не нужно разрешение `INTERNET` — и не понадобится даже после появления
синхронизации.** Целевая схема синка — общая папка, которую реплицирует стороннее приложение
(Syncthing/iCloud Drive); само приложение работает только с файлами. Манифест без `INTERNET`
остаётся частью спецификации, но как следствие выбранной схемы синка, а не как отказ от него.

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Язык | Kotlin 2.x | Стандарт для Android |
| UI | Jetpack Compose + Material 3 | Динамические цвета One UI, меньше кода, чем XML |
| БД | Room (SQLite) | Реляционная модель из документа 01 ложится один-в-один |
| Настройки | DataStore (Preferences) | Только локальные мелочи устройства (последняя вкладка и т.п.). Всё пользовательское, включая профиль, — в Room, иначе не переживёт смену телефона (05 §1.2) |
| Аудио | `MediaRecorder` (запись) + `ExoPlayer/Media3` (прослушивание с метками) | Ранты, act-out, запись выступлений |
| Распознавание речи | `SpeechRecognizer` офлайн (`EXTRA_PREFER_OFFLINE`) — **best-effort** | API рассчитан на короткие фразы: длинный рант распознаётся сегментами со склейкой, качество не гарантируется. Аудио всегда первично. Путь апгрейда — whisper.cpp на устройстве (05 §3.1) |
| Навигация | Navigation Compose, single-activity | 5 вкладок |
| DI | Ручной `AppContainer` | Hilt/KSP — лишняя точка отказа в CI ради приложения на одного пользователя |
| Сериализация | kotlinx.serialization | `exercises.json` в assets, экспорт |
| Фон | WorkManager | Только напоминание об утренних страницах |
| minSdk / target | 26 / 35 | Для S24 Ultra без разницы, но раздача знакомым — заявленный сценарий; запас версий на Compose стоит ноль (05 §3.3) |

**Осознанно не берём:** Hilt, Firebase, аналитику, Crashlytics, облако, ИИ-интеграции.
Каждая из них тянет сеть или сложность, которых цель проекта не оправдывает.

## 3. Как это попадёт на телефон — и главное препятствие

**Установлено проверкой окружения:** в этом контейнере `dl.google.com` заблокирован
сетевой политикой (403 на CONNECT). Через него раздаются Android SDK, Android Gradle Plugin
и все артефакты AndroidX/Compose (`maven.google.com` — редирект на тот же хост).
Maven Central и Gradle доступны, Java 21 и Gradle 8.14 стоят.

**Вывод: собрать APK прямо здесь сейчас нельзя.** Три пути, в порядке предпочтения:

### Путь A (основной) — сборка в GitHub Actions
На раннерах `ubuntu-latest` Android SDK предустановлен, сеть открыта.
Workflow `.github/workflows/android.yml`: сборка APK, подписанного release-ключом
из GitHub Secrets → артефакты/Releases → скачиваешь на телефон и ставишь (в One UI разрешить
установку из браузера/файлового менеджера).
**Это делает CI не «хорошей практикой», а единственным каналом доставки, поэтому его
настраиваем в самом первом шаге — до какого-либо кода приложения.**
Для раздачи знакомым: Obtainium читает только публичные GitHub Releases; у приватного
репозитория получателю нужен токен, либо APK пересылается файлом (05 §3.3).

### Путь B (ускоритель) — открыть `dl.google.com` в настройках окружения
Если разрешить этот хост в network policy окружения Claude Code, я собираю APK локально,
итерации становятся быстрее (минуты вместо цикла коммит→CI→скачивание).
Путь A при этом остаётся как способ доставки.

### Путь C (запасной) — Android Studio на твоей машине
Клонируешь репозиторий, жмёшь Run. Нужен установленный Android Studio и ~10 ГБ на SDK.

> Первый шаг M0 ниже проверяет именно это: пока в GitHub Actions не соберётся пустое
> приложение с одной надписью на экране, писать остальное бессмысленно.

## 4. Этапы

Этапы упорядочены так, чтобы **после каждого на телефон вставал работающий APK**,
и каждый следующий добавлял ценность, а не «ещё один слой инфраструктуры».

### M0 — Скелет и канал доставки
- Пустой проект, **финальное** имя пакета `ru.punchline.workbook`, приложение **«Панчлайн»**.
- Модули с первого дня: `:core:model` (чистый Kotlin, ни одного Android-импорта) /
  `:core:data` (обычная Android-библиотека; в сущностях и DAO запрещены Android-типы) / `:app`.
  Сама KMP-конфигурация — в v2; сейчас только дисциплина, делающая её механической (05 §2.2).
- Gradle version catalog, Compose, тёмная тема по умолчанию (нужна для режима сцены).
- **Release-keystore**, ключ и пароли в GitHub Secrets, копия в менеджере паролей.
  Подпись им всех сборок с первой же — смена ключа позже означает переустановку с потерей данных.
- `.github/workflows/android.yml`: сборка подписанного APK + публикация в артефакты/Releases.
- Манифест **без** `INTERNET`; `allowBackup=false`.
- Правило: ни одной строки русского текста в коде, только `strings.xml`.
- ✅ Критерий: APK скачан из Actions, установлен на S24 Ultra, открывается.

### M1 — Хранилище и быстрый захват
- Room-схема: `Topic`, `Bit`, `BitVersion`, `Rant`, `MorningWritingEntry`, `Streak`, `AudioFile`.
- **Готовность к слиянию (см. документ 04):** UUIDv7 как первичный ключ; поля
  `updatedAt` / `deletedAt` / `deviceId` / `lamport` во всех сущностях; мягкое удаление;
  аудиофайлы адресуются по SHA-256 содержимого; все изменения идут через единый `MutationSink`.
- Экран Inbox + FAB «Записать»: текст или голос в один тап → `Bit(seed)`.
- Запись/воспроизведение аудио, файлы во внутреннем хранилище приложения.
- Быстрый доступ: ярлык на рабочий стол (App Shortcut) прямо на запись.
- ✅ Критерий: идея, пойманная в метро, попадает в приложение за 3 секунды и не теряется.

### M1.5 — Экспорт, импорт, смена телефона
- Формат хранилища: `manifest.json` + `vault.sqlite` + `blobs/<hash>` (описан в документе 04).
- Экспорт — **один ZIP-файл** через `ACTION_CREATE_DOCUMENT` (экспорт папкой через SAF
  недопустимо медленный на сотнях блобов — 05 §3.2); импорт с проверкой хешей и версии схемы.
- Тест полного цикла: экспорт → удаление приложения → чистая установка → импорт → данные на месте.
- ✅ Критерий: смена телефона перестаёт быть риском. Дальше можно спокойно накапливать материал.

### M2 — Мастерская (ядро методики, Part Two)
- Темы: брейншторм → оценка страсти → выбор 3 главных.
- Mind-map: дерево-аутлайн (вложенный список), узел → `Bit(seed)`. Свободный холст с S Pen —
  сознательно вырезан из v1 как самый дорогой экран проекта (05 §2.1).
- Рант: диктофон + офлайн-транскрипт, выделение фрагмента → премиса.
- Визард шутки: attitude (hard/weird/scary/stupid) → премиса → панч (mix/turn/list of three)
  → act-out → space work → теги. Выход на любом шаге, прогресс сохраняется.
- Доска «Шутки в работе», сгруппированная по темам, с фильтрами.
- ✅ Критерий: путь «тема → рант → готовый черновик шутки» проходится целиком в приложении.

### M3 — Тетрадь: 48 упражнений и утренние страницы
- Движок форм: рендер экрана упражнения из `inputSchema` (документ 02).
- `exercises.json` в assets; экран редактирования справочника (для 7 неизвестных названий
  и 30 промптов — вносятся руками, без пересборки).
- Утренние страницы: таймер, свободное письмо, «выделить и собрать в шутку» (harvest).
- Цепочка Сайнфелда: календарь-сетка, локальное напоминание через WorkManager
  (+ запрос runtime-разрешения `POST_NOTIFICATIONS`, без него на Android 13+ напоминаний нет).
- ✅ Критерий: все 48 упражнений открываются и сохраняют ответы; цепочка считается.

### M4 — Сет-листы и режим сцены
- Конструктор сета: цель по времени, drag & drop, роли (открытие/тело/закрытие/каллбэк).
- Проверки движка: каллбэк не раньше исходной шутки, две подряд шутки на одну тему, хронометраж.
- **Режим сцены**: тёмный экран, cue-слова крупно, экран не гаснет, таймер обратного отсчёта,
  вибро на «свет», автозапись выступления.
- ✅ Критерий: реальный открытый микрофон отработан по телефону в кармане, аудио записано.

### M5 — Обратная связь со сцены (упражнения 34–36)
- Гиг: разбор после выступления, оценка каждой шутки одним тапом
  (тишина / хмык / смех / гогот / аплодисменты).
- Плеер записи с расстановкой меток по ходу прослушивания.
- Laugh score, LPM, воронка `seed→…→polished`, перекос по attitude, доля шуток с act-out.
- Автоматические переходы статусов и подсказки («3 раза тишина — перепиши премису»).
- «Мой акт»: только отшлифованное, прогресс к цели по минутам.
- ✅ Критерий: после выступления акт сам пересобирается по данным, а не по ощущениям.

### M6 — Полировка
- Экспорт в Markdown по пяти секциям тетради (для чтения глазами, в дополнение к бэкапу из M1.5).
- Глобальный поиск по тексту и транскриптам.
- Виджет быстрого захвата (Glance), опционально.
- ✅ Критерий: приложением приятно пользоваться каждый день, а не только «оно работает».

**v2:** Mac-приложение (`:desktop` на Compose Multiplatform поверх общего `:core`) +
синхронизация журналами операций через общую папку (`:core:sync`) + Comedy Buddy.

## 5. Риски и что с ними делать

| Риск | Вероятность | Что делаем |
|---|---|---|
| `dl.google.com` заблокирован → нельзя собирать здесь | **подтверждён** | Путь A (GitHub Actions) как основной канал; путь B по желанию |
| Офлайн-распознавание русской речи на устройстве работает плохо или недоступно | средняя | Аудио — всегда первично и сохраняется; транскрипт опционален. Приложение полностью работоспособно без него |
| Медленный цикл итераций через CI | высокая | Максимум логики покрыть unit-тестами (Room + доменные правила), которые гоняются в CI без устройства; на телефон выносить только проверенное |
| Схема БД поедет при добавлении полей | высокая | Room-миграции с первого дня, экспорт схемы в `app/schemas`, тест миграций |
| 7 неизвестных упражнений и 30 промптов | подтверждён | Редактируемый справочник в самом приложении — не блокирует ни один этап |
| Перегрузить приложение и бросить | **главный** | Каждый этап даёт устанавливаемый APK. Если бросить после M2 — уже есть работающая мастерская шуток |
| Ретрофит синхронизации на локальную схему | высокая, если не готовиться | Пять решений M0–M1 из документа 04 (UUID, tombstones, `updatedAt`, хеши, `MutationSink`). Цена — примерно день работы сейчас |
| Потеря телефона до появления бэкапа | средняя, последствия тяжёлые | Экспорт/импорт перенесён с M6 на M1.5 |

## 7. Состояние

Все этапы M0–M6 реализованы и лежат в ветке `claude/comedy-joke-app-kdwyxa`.

| Этап | Что сделано |
|---|---|
| M0 | Три модуля, version catalog, CI со сборкой подписанного APK, доменное ядро с тестами |
| M1 | Room-схема на 16 таблиц, репозитории, диктофон, входящие и быстрый захват |
| M1.5 | Перенос данных одним ZIP: формат в `:core:vault`, полный цикл смены телефона под тестом |
| M2 | Темы, оценка страсти, три главные, дерево ассоциаций, визард шутки |
| M3 | 48 упражнений, утренние страницы, цепочка Сайнфелда |
| M4 | Сет-листы с проверками движка, режим сцены |
| M5 | Разбор выступления, laugh score, автоматическая пересборка акта |
| M6 | Экран «Сегодня», статистика, выгрузка в Markdown |

**Что осталось за рамками v1 и почему**

- Распознавание речи не подключено. `SpeechRecognizer` рвётся на длинной
  непрерывной речи, и делать его частью критического пути нельзя — аудио
  пишется и хранится, транскрипт добавится отдельной задачей (whisper.cpp).
- Напоминание об утренних страницах через WorkManager и разрешение
  `POST_NOTIFICATIONS` — не подключены.
- Виджет быстрого захвата (Glance).
- `android.newDsl=false` и `android.builtInKotlin=false` — временная развилка,
  переход на built-in Kotlin отдельной задачей.

**Первый шаг для владельца:** добавить четыре секрета репозитория, скачать
подписанный APK из артефактов Actions и поставить на телефон.
